## Schema

All result files share this base schema:

```
seed                 int       random seed
baseline             str       e.g. "XGBoost values-only", "Oracle (upper bound)"
accuracy             float     overall accuracy on the held-out test split
fk_break             float     recall on fk_break instances
cardinality_break    float     recall on cardinality_break instances
derivation_break     float     recall on derivation_break instances
transition_break     float     recall on transition_break instances
```

Experiment-specific extra columns:

- `scaling_curve_results.csv`: adds `n_train_pairs`
- `tabpfn_results.csv`: per-instance `P_legal` predictions and per-seed mean/std
- `mi_*_results.csv`: `mi_nats`, `null_mean_nats`, `z_score`, `p_shuffle`

### Pilot follow-up (initial 10-state, 200-customer)

10 zero-shot states with full source artifacts (schema, trigger, procedural rule tables) supplied to two frontier reasoning models in a single prompt, 64k output-token budget for each.

|                                | Kimi-K2.6 | GPT-5.5 |
|--------------------------------|-----------|---------|
| Overall accuracy               | 5/10      | 5/10    |
| Recall on ILLEGAL              | 5/5       | 5/5     |
| Precision on LEGAL             | 0/5       | 0/5     |
| Violation type (illegal-state) | 4/5       | 2/5     |
| Empty / token-capped           | 1/10      | 0/10    |
| Mean wall time per state       | ~210 s    | ~24 s   |

### Matched 100-state source-artifact controls

After the initial pilot we ran matched 100-state source-artifact controls on
the 50-customer export (50 legal + 50 illegal states). The models receive the
schema, trigger source, procedural rule description, and state CSVs. Overall
accuracy is secondary because the dominant failure mode is asymmetric: models
often label illegal states correctly while rejecting legal states.

| Run                         | Accuracy          | LEGAL on legal states | Illegal states labelled illegal | Violation type correct on illegal states | EMPTY / token-capped |
|-----------------------------|-------------------|-----------------------|----------------------------------|------------------------------------------|----------------------|
| GPT-5.5 default prompt      | 50/100 = 0.50     | **0/50**              | 50/50                            | 30/50                                    | 0/100                |
| GPT-5.5 high effort         | 50/100 = 0.50     | **0/50**              | 50/50                            | 41/50                                    | 0/100                |
| GPT-5.5 + SQL executor      | 50/100 = 0.50     | **0/50**              | 50/50                            | 29/50                                    | 0/100                |
| Kimi-K2.6                   | 46/100 = 0.46     | **2/50**              | 44/50                            | 39/50                                    | 14/100               |

**The headline result:** GPT-5.5 accepts 0/50 legal states in every matched
100-state condition, including high reasoning effort and SQL execution.
Kimi-K2.6 accepts 2/50 legal states and is partly output-budget limited. The
seven rule-derived audit features remain unbeaten (0.9996 vs. 0.46-0.50), with
deterministic verdicts.

A subsidiary finding: arithmetic violations (`derivation_break`) are the
hardest for the SQL-tool condition. GPT-5.5 + SQL labels all illegal states as
illegal, but recovers 0/17 derivation violation types. Tool use helps query
execution, but does not supply the missing operational convention.

### Smaller diagnostic controls

The earlier verify-legality and 128k-budget Kimi runs are retained as
diagnostics. The verify-legality control replaces the system prompt's "find any
violation" framing with "default to LEGAL unless you can identify a specific
violating row." It accepts 3/50 legal states for Kimi-K2.6 and 0/49 non-empty
legal states for GPT-5.5. A higher-budget Kimi diagnostic accepts 1/25 legal
states.

### Trace asymmetry

The two models expose very different amounts of their reasoning:

- **Kimi-K2.6** writes its chain-of-thought to `message.reasoning_content`, a non-standard field on the model's response (non-standard `reasoning_content` field). Each state has both a `.content.txt` (the final JSON, ~50 bytes) and a `.reasoning.txt` (the chain-of-thought, 60-100 KB). The reasoning traces are readable transcripts of an audit-in-progress: enumerating customers, checking order totals against the discount and tax tables, hypothesising violations, ruling them out.
- **GPT-5.5** returns only `message.content` (the final JSON). the GPT-5.5 hosting endpoint hides chain-of-thought; the only signal we have on its reasoning is `usage.completion_tokens_details.reasoning_tokens`. Each state has a `.content.txt` (~50 bytes); there is no `.reasoning.txt`.

A second observation worth flagging in any extension of this experiment: GPT-5.5 used exactly $512$ reasoning tokens on 8 of 10 states (the other two: $256$ on `fk_break`, $158$ on one LEGAL state). That is a suspiciously round default and likely reflects an unset `reasoning_effort` parameter. We did not vary that here. A follow-up with `reasoning_effort="high"` may change the picture, especially on the legal-state false positives where 512 reasoning tokens may simply not be enough to examine all 6,000 line items.

Per-state traces are in `kimi_traces/`. Each state has up to two files:

```
kimi_traces/test_NNNNNN.content.txt    final JSON answer (or absent if EMPTY)
kimi_traces/test_NNNNNN.reasoning.txt  full chain-of-thought from message.reasoning_content
```
